# MK功能清单编写

用于把分散资料整理成一份可交付的模块功能清单 Excel。

## 何时使用

当用户出现以下任一需求时使用本 Skill：

- “根据操作手册/需求文档整理模块功能列表”
- “根据 PRD 输出一份模块功能清单”
- “结合发版清单输出某模块的功能清单”
- “参考某个 Excel 样例生成模块功能表”
- “根据系统截图、手册、发布清单盘点模块能力”
- “基于 `MK需求文档编写` 生成的 PRD 继续产出功能清单”

## 默认输出

- 优先使用用户明确提供的 Excel 模板。
- 若用户未提供模板，默认使用 `assets/功能清单模板.xlsx`。
- 默认输出文件名：`{模块名称}功能列表.xlsx`
- 默认输出结构：`功能分类 | 功能子项 | 功能备注`

## 工作流程

### 1. 锁定范围

- 先确认本次只整理**一个模块**或**一个明确子域**。
- 若资料中包含多个模块，只抽取用户指定模块；不要把相邻模块内容混入。
- 若用户给了版本信息，输出时以该版本为准。

### 2. 按资料角色吸收信息

- **操作手册 / 产品手册**：用于建立模块菜单树、页面入口和完整功能基线。
- **需求文档 / 方案文档**：用于识别目标范围、能力边界和业务术语。
- **PRD（含由 `MK需求文档编写` Skill 生成的多文件 PRD）**：用于直接提取已确认的模块范围、用户故事、页面清单、实体清单和能力描述，是“需求已结构化”场景下的优先输入。
- **发版清单 / 发布说明**：用于补充该版本新增、优化、下线的能力点。
- **系统截图**：用于确认菜单结构、页签、页面名称和界面承载方式。
- **既有功能表 / 样例 Excel**：仅用于参考风格、结构和粒度，不可直接照搬文案。

### 2.1 PRD 直出功能清单线路

- 当用户提供的是 PRD，尤其是由 `MK需求文档编写` Skill 生成的 PRD 时，优先走“PRD → 功能清单”线路，而不是回退到截图或零散手册逐页猜测。
- 若为多文件 PRD，至少要读取：
  - 主文件中的产品定位、用户角色、功能清单、导航菜单、页面清单
  - `stories/` 中各用户故事的页面目标、能力描述、关键操作闭环
  - `models/` 中实体名称、实体职责、机制归属
- PRD 已明确的页面、故事、机制、实体关系，可直接作为功能抽取依据；仅当 PRD 未覆盖或版本边界不清时，再补充读取手册、发版清单、截图。
- 若 PRD 与其他资料冲突，默认优先采用与目标版本一致、且在 PRD 中已被明确确认的内容。

### 3. 先提炼，再归并

- 先抽取原子功能点，再按菜单或能力域归并。
- 同一菜单下的多个按钮/页签/操作，如果共同服务于一个能力主题，应合并为一条“功能子项”。
- 不要把“查询、分页、搜索、筛选、导出”机械拆成多条，除非它们本身是独立能力模块。
- 若来源是 PRD，先从“用户故事 → 页面 → 实体 / 机制”还原能力闭环，再归并到菜单或能力域，不要直接把故事标题逐条抄成“功能子项”。

### 4. 写入模板时遵循三列口径

- **功能分类**：粗粒度分组，通常是 `{模块名称}后台管理`、`{模块名称}用户端`、`移动与开放能力` 这类层级。
- **功能子项**：菜单、页签或能力域名称，如“设计中心”“监控中心”“业务流查询”“开放接口与系统集成”。
- **功能备注**：写成能力描述，不写成操作步骤。

## 功能备注写法

每个“功能备注”按以下结构组织：

1. 先用 1 句话概括“提供什么能力”
2. 再用 `1、2、3...` 分点说明能力范围
3. 描述重点放在：
   - 能解决什么问题
   - 支持哪些核心能力
   - 适合什么场景

避免以下写法：

- 照抄样例模板原句
- 仅罗列按钮名、分页器、复选框等界面碎片
- 把页面操作路径写成大段说明
- 仅凭截图脑补不可见能力

## 输出风格要求

- 风格要**接近样例模板**，但**绝不照搬样例文案**
- 文案要偏“能力盘点/平台说明”，不是“测试步骤”或“页面使用手册”
- 能合并的内容尽量合并，减少碎片化条目
- 若同一能力既有后台管理又有用户端入口，应分两条写，避免混淆角色视角

## 冲突处理

- 若手册与发版清单冲突，优先采用**更贴近目标版本**且**更具体**的资料
- 若 PRD 与手册/截图冲突，优先采用**已确认版 PRD** 中对目标模块的明确描述，再用其他资料补边界
- 若截图与文档冲突，截图只用于确认页面存在，不单独推翻文档能力定义
- 若资料不足以证明某项能力存在，宁可保守描述，不要补全想象内容

## 生成 Excel 时的要求

- 保持模板原有三列结构
- 第一列允许按分类做合并单元格
- 第三列需开启自动换行，便于容纳能力说明
- 若用户给的是样例模板，应复制模板后填充，不直接修改原文件

## 自检清单

输出前必须检查：

- 是否只覆盖了目标模块
- 若输入是 PRD，是否已覆盖主文件、故事文件、实体文件三层信息，而不是只读了目录或标题
- 是否已合并重复或过细的条目
- 是否按“功能分类 / 功能子项 / 功能备注”落表
- 功能备注是否为能力描述而非操作步骤
- 是否明显参考了样例风格，但没有照搬样例话术
