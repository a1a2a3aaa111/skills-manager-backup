# 功能清单口径

## 一、资料角色划分

| 资料类型 | 主要作用 | 使用原则 |
| --- | --- | --- |
| 操作手册 / 产品手册 | 建立完整菜单和功能基线 | 优先提取一级菜单、二级菜单、页签、核心能力 |
| 需求文档 / 方案文档 | 明确目标范围和业务边界 | 用于识别“这次只整理哪些内容” |
| PRD（含 `MK需求文档编写` 输出的多文件 PRD） | 提供结构化的模块能力定义 | 优先提取主文件的功能框架、stories 的能力闭环、models 的实体职责 |
| 发版清单 / 发布说明 | 标识新增、优化、下线项 | 用于补充版本差异，不替代完整功能基线 |
| 页面截图 | 验证菜单结构、页面名称、承载方式 | 只确认可见事实，不单独推断隐藏能力 |
| 样例 Excel | 参考结构、粒度、文风 | 学风格，不抄内容 |

## 二、PRD 资料使用口径

当输入资料是 PRD，尤其是 `MK需求文档编写` Skill 输出的多文件 PRD 时，按以下顺序抽取：

1. **先读主文件**

- 提取模块名称、版本范围、用户角色、导航菜单、页面清单、功能框架概述
- 主文件中的功能清单与页面清单，用于建立一级分组和能力边界

2. **再读 stories/**

- 每个故事重点提取：该故事解决什么业务问题、覆盖哪些页面、形成什么能力闭环
- 不直接把“故事标题”照抄成功能子项，而是把同类故事归并为一个能力域或菜单能力
- 同一故事中的多个按钮、状态页签、处理动作，若共同服务一个业务闭环，应收敛为一条能力描述

3. **补读 models/**

- 用于确认实体职责、业务对象边界、机制归属
- 实体文件主要帮助判断“该能力是在做什么业务对象管理”，不用于把字段级内容逐项写入功能清单

4. **PRD 与其他资料的优先级**

- 已确认版 PRD > 同版本发版清单 > 操作手册 > 截图
- 若 PRD 未覆盖某块能力，再用手册或截图补充，但必须保持与 PRD 已确认范围一致

## 三、推荐分组方式

根据模块形态，从以下结构中选择最贴合的一种：

### 模式 A：后台 + 用户端 + 扩展能力

- `{模块名称}后台管理`
- `{模块名称}用户端`
- `移动与开放能力`

适用：业务流、流程平台、知识中心、审批中心这类同时存在后台配置和前台使用的模块。

### 模式 B：纯后台平台

- `{模块名称}平台管理`
- `{模块名称}运行监控`
- `{模块名称}开放与运维`

适用：偏中后台、偏平台治理的模块。

### 模式 C：纯用户侧业务模块

- `{模块名称}业务办理`
- `{模块名称}查询与跟踪`
- `{模块名称}移动与集成`

适用：只有前台业务操作、没有明显后台配置面的模块。

## 四、功能子项粒度

优先按下面顺序确定“功能子项”：

1. 菜单名
2. 页签名
3. 独立能力域

例如：

- 好：`设计中心`
- 好：`监控中心`
- 好：`开放接口与系统集成`
- 一般：`新建`
- 不推荐：`查询按钮`

## 五、功能备注写法

推荐格式：

```text
XXX用于提供某类能力。
1、……
2、……
3、……
```

推荐写法示例：

```text
监控中心用于提供流程实例全生命周期监控与干预能力。
1、支持按全部、进行中、已完成、异常等状态统一查看实例。
2、支持查看当前活动、流程状态、处理进度和责任人等关键信息。
3、支持授权管理员执行前后跳转、终审通过、直接废弃等特权操作。
```

不推荐写法示例：

```text
点击监控中心后进入列表页，右上角有按钮，支持分页、筛选、导出。
```

原因：这是页面操作说明，不是功能能力描述。

## 六、合并规则

遇到以下情况应合并：

- 同一菜单下多个按钮共同完成一个能力闭环
- 同一页签下多个操作本质上服务同一治理场景
- 同类状态页（如全部 / 进行中 / 已完成）本质是同一查询能力的不同视图

遇到以下情况不应合并：

- 后台治理与用户端使用是两个不同视角
- PC 端与移动端承载能力明显不同
- 开放接口能力与页面能力混在一起会导致理解模糊

## 七、常见风险

### 1. 把截图元素当成功能

分页、复选框、刷新按钮、搜索框本身通常不是独立功能。

### 2. 把发版项当全部能力

发版清单只能说明某个版本变更过什么，不能替代模块完整功能图谱。

### 3. 只看 PRD 标题不看内容

多文件 PRD 的能力信息往往分散在主文件、stories、models 中；如果只看目录、标题或第 5 章摘要，容易漏掉关键闭环。

### 4. 把样例文案原样换模块名

应保留结构和表达层次，但必须根据目标模块重新组织内容。

### 5. 功能子项过碎

如果一页里同时出现“新建、编辑、删除、查看引用”，通常应收敛为“模板管理能力”或“事件管理能力”。
